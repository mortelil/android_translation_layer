## Findings and repairs

- OMP's broad terminal calls bypassed actual Java callers of Activity native
  methods. Internal paths now return pending, with checks between callbacks;
  native-owned startup/GTK/GLib callers route uncaught exceptions. Java catch
  tests witness object identity across both start and resume. This preserves
  existing ContextImpl/Instrumentation catch opportunities; their own wrapping
  or fallback behavior is not replaced. Resume preserves original successful
  callback ordering; on failure it skips further callbacks and cleans references.
- The original local Throwable reference already roots the object. Removed the
  unnecessary NewGlobalRef allocation/failure path, which discarded diagnostics.
- Fallback method IDs previously came from the original subclass and were used
  on differently typed causes. Resolve on Throwable instead. Check sequential
  lookups and GetStringUTFChars failure before any further ordinary JNI.
- Original analyzer B accepted JVM startup plus an otherwise empty scenario.
  It now requires the expected identity witness, fallback diagnostic, cause,
  formatter failure and terminal path. A requires a terminal diagnostic too;
  positive controls reject native fatal records. Stale run directories refused.
- Fresh probes initially used invokedynamic lambdas and exposed the pinned
  runtime's BootstrapMethodError. Rebuilt as anonymous classes, without changing
  runtime behavior or weakening the tested JNI contracts.
