# File-backed typefaces

`Typeface.Builder(File/String)` and `createFromFile` load font files using
Fontconfig and Pango. Each file face has a private font map, with system fonts
available for fallback. A private family alias prevents an installed font with
the same family name from replacing the requested file. The selected collection
index is checked before a typeface is returned.

The font map owns an open descriptor to the file. Fontconfig uses its
`/proc/self/fd` path so delayed glyph loading still works after the application's
temporary pathname is removed. Typeface copies, Paint copies and Pango layouts
retain references to the map; native cleanup releases those references.

Paint measurement, Canvas text, Layout, TextView and EditText use the selected
font. TextPaint now copies its Paint base state. Paint measurement uses shaped
Pango advances rather than a fixed per-character estimate. Style copies retain
the file map and preserve the Paint text size.

Invalid or missing files return null from Builder unless an explicit fallback
family was supplied. `createFromFile` throws on failure. Weight, italic, collection
index and string variation settings are supported through Pango; variation axes
only affect fonts that provide those axes.

## Validation and limits

`tests/mobile-smoke/TestTypeface.java` loads DejaVu Sans Mono, removes the
temporary file before glyph loading, compares narrow/wide glyph advances with
a proportional font, and checks Paint copying, layout metrics, styles, explicit
fallback and invalid input. It also exercises TextView and EditText font changes.
Original rectangle-glyph fixtures generated by `font-fixtures.py` verify that
both variation-setting overloads change advances and that collection indices
select different faces. String parsing, style-span updates and malformed settings
are checked as well.
Run `scripts/mobile/test.sh` in the Alpine development environment with Xvfb;
the fixtures require Alpine's `font-dejavu` and `py3-fonttools` packages.

This is not complete Android font compatibility. The older asset and FontFamily
entry points still return the default face; FileDescriptor builders are not
implemented. Pango cannot encode variation tags containing comma or equals;
these are explicitly rejected. Pango shaping and fallback
can differ from Android Minikin/Skia. TextView assertions check state and successful
GTK application, not pixel-identical rasterization. GTK widget font changes must
run on the UI thread.
Concurrent use of the same private font map from several threads has not been
validated; map ownership/thread isolation needs review before upstream submission.

TypefaceSpan supports its family and Typeface constructors and applies their
different style-preservation rules to draw/measure TextPaint. General span
rasterization is still limited: the existing TextSpanAttributes bridge handles
color and size, not per-range font maps. Parcel transport is not implemented.

Written with AI assistance; no AOSP font implementation was copied.
